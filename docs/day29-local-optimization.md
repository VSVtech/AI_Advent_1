# День 29 — оптимизация локальной Qwen для RAG

Задача профиля — короткие ответы разработчику по документации проекта с точными
ссылками на подтверждающие цитаты. Это настройка инференса и входного шаблона,
без дообучения весов. Все экспериментальные ответы получены локально через Ollama;
облачные модели не использовались.

## В приложении

«Новый агент» → локальная Qwen. Температура, размер контекста и максимальный
размер ответа задаются независимо в трёх числовых полях. Диапазоны приложения:
0–2, 100–32 768 и 50–8192 токена соответственно; ответ должен быть меньше контекста.
Начальные значения — 0, 16 384, 1536. Выбранные значения сохраняются с агентом
и передаются генератору; размер контекста также применяется к локальной памяти.

При включённом RAG флажок **«Использовать шаблон ответа для базы знаний»**
переключает специальный/стандартный шаблон, схему вывода и представление каталога.
Он не сбрасывает и не переопределяет числовые настройки. Проверки цитат работают
в обоих режимах. Для воспроизведения исходного эксперимента выставьте его параметры
вручную: 0.3 / 32 768 / 8192 и выключите специальный шаблон.

Ниже сохранены фиксированные профили замеров от 9 октября. Обновление интерфейса
11 октября добавляет произвольные параметры, но не меняет исторические результаты.

| Настройка генератора | Исходный профиль | Оптимизированный профиль |
| --- | --- | --- |
| temperature | 0.3 | 0 |
| num_ctx | 32 768 | 16 384 |
| num_predict | до 8 192 | до 1 536 |
| Формат | JSON | JSON Schema для фактов и ссылок |
| Шаблон | общий шаблон проверяемого ответа | краткий ответ по документации, минимальные нужные команды |
| Каталог цитат | группировка по источникам | у каждой цитаты явно указаны source_id и quote_id |

Профиль находится в `lib/local-rag-profile.ts`. Он сохраняет все допущенные
цитаты, исходные идентификаторы и данные списков. Поиск, пороги, проверка точного
вхождения цитаты, смысловая проверка и режим «не знаю» остаются прежними.
Уменьшение окна не должно незаметно обрезать документы: сервер отклоняет запрос,
если оценка контекста вместе с резервом ответа превышает окно. Для длинных
диалогов исходный профиль остаётся доступен. Анализатор памяти получает выбранное пользователем окно, чтобы не переключать
размер контекста той же модели между шагами.

## Как измеряли

8 вопросов: порт, команда запуска, модель эмбеддингов, история, обращение с API-
токеном, уточняющий вопрос с историей и два вопроса без подтверждения в базе.
Ожидания находятся в `rag/local-optimization-questions.json` и не передаются модели.

Поиск выполнен один раз, результат сохранён в снимке. Все профили получают одни и
те же фрагменты из одного индекса. Меняются параметры генерации, шаблон и форма
представления каталога. Это изолированный замер генератора: время поиска,
MemoryCurator и последующей смысловой проверки не включено. Оно не равно времени
полного ответа в чате.

Финальный прогон: один ответ на вопрос на профиль, seed 42, перед каждым вопросом
модель выгружается, загружается коротким прогревом и получает новый контекст.
Прогрев и загрузка весов исключены из времени ответа. Тем самым предыдущий ответ
не ускоряет следующий за счёт кэша длинного префикса. Малый набор и единичные
замеры не доказывают статистически устойчивое ускорение; фоновые процессы тоже
влияют на скорость.

Сохраняются TTFT, полное время генерации, входные/выходные токены, скорость
генерации и максимальные наблюдавшиеся `size`/`size_vram` из `/api/ps` (опрос каждые
500 мс). Это выделенная Ollama память **одной модели**, а не пиковая память всего
процесса/приложения. На Metal это общая память: значения size и size_vram не нужно
складывать. Тестовый компьютер имеет 48 GiB RAM.

Автоматическая оценка проверяет структуру, существование дословных цитат, ожидаемые
ключевые признаки в ответе **и в выбранных цитатах**, источник и правильный отказ.
Она не заменяет смысловую проверку. В отчёте также отдельно разобраны реальные
пары «утверждение — цитата».

В первых пробах проверка только текста давала ложные 8/8: модель могла правильно
назвать порт, но сослаться на фразу о другом компоненте. Также ранний компактный
шаблон добавлял команды установки к вопросу только о запуске. Эти наблюдения
привели к более строгой оценке, уточнению шаблона и явным парам идентификаторов
рядом с цитатами. Метки dev/test сохранены для воспроизводимости, но вопросы test
уже участвовали в доработке: это проверочный набор, **не независимый слепой тест**.

## Воспроизведение

Требуется Node.js с поддержкой прямого импорта TypeScript (в этом прогоне 26.8.1).
Сначала запустите Ollama и при необходимости скачайте обе квантованные версии
одной Qwen2.5 7B:

```bash
pnpm rag:ollama
ollama pull qwen2.5:7b
ollama pull qwen2.5:7b-instruct-q8_0
```

Q4_K_M уже использовалась в приложении. Для сравнения скачана готовая официальная
Q8_0, а не повторно квантована Q4. Веса занимают примерно 4.7 и 8.1 GB на диске.
Скачивание требует сети; генерация остаётся локальной.

Для нового снимка запустите `pnpm rag:server` с существующим индексом и выполните:

```bash
pnpm local:benchmark prepare
pnpm local:benchmark run --profile=baseline --repeat=1 --fresh-context
pnpm local:benchmark run --profile=compact --repeat=1 --fresh-context
pnpm local:benchmark run --profile=compact --model=qwen2.5:7b-instruct-q8_0 --repeat=1 --fresh-context
```

Запускайте последовательно, без других запросов к Ollama. Результаты и снимок
пишутся в `.local-data/day29/`; JSON содержит ответы без исправлений, параметры,
хеши шаблона, набора и снимка, digest модели, метрики и ошибки. Повторять эксперимент
можно с `--repeat=2` и более. Для сохранённого снимка используйте
`--snapshot=rag/day29-results/retrieval.json`; этап prepare тогда не нужен.

[Ollama Chat API: параметры, JSON Schema и длительности](https://docs.ollama.com/api/chat),
[значения памяти работающих моделей](https://docs.ollama.com/api/ps),
[Qwen2.5 7B Q8_0](https://ollama.com/library/qwen2.5:7b-instruct-q8_0).

## Результаты 9 октября 2026

Изолированные **первые черновики генератора**, до исправления и смысловой проверки
в приложении. PASS требует правильного ответа и подходящих цитат; два корректных
отказа также входят в оценку. Все 24 запроса завершились без сетевой ошибки,
обрезания вывода или некорректного JSON. Корректная структура не означает
корректный смысл.

| Вариант | Ответ + цитаты | Медиана, 8 вопросов | Медиана, 6 вопросов с контекстом | Память модели, GB |
| --- | ---: | ---: | ---: | ---: |
| Q4_K_M, исходный | 5/8 | 11.83 с | 12.44 с | 6.58 |
| Q4_K_M, оптимизированный | 6/8 | 12.78 с | 12.95 с | 5.61 |
| Q8_0, оптимизированный | 7/8 | 12.59 с | 13.51 с | 8.75 |

GB — десятичные миллиарды байт. Окно 16K уменьшило выделенную память Q4 на
14.8%. Переход на Q8 увеличил память на 56.1% относительно настроенной Q4.
Ускорения не получилось: у настроенной Q4 медиана всех вопросов выше на 8.1%.
Более явное представление источников удлиняет вход и требует дополнительной
обработки. На двух вопросах без источников замеряется генерация отказа; в
приложении такие случаи могут завершиться раньше, без вызова генератора.

Проверка по каждому вопросу (автоматическая оценка и просмотр пар «факт — цитата»):

| Вопрос | Q4 исходный | Q4 оптимизированный | Q8 оптимизированный |
| --- | --- | --- | --- |
| Порт RAG-сервиса | Неверная цитата | PASS | PASS |
| Команда запуска RAG | Неверная цитата | Неверная цитата | PASS |
| Модель эмбеддингов | PASS | PASS | PASS |
| SLA восстановления | Правильный отказ | Правильный отказ | Правильный отказ |
| Сохранение истории | Неверная цитата | PASS | PASS |
| API-токен и браузер | PASS | PASS | PASS |
| Запуск с ранее выбранным pnpm | PASS | Перепутан сервис | Перепутан сервис |
| Стоимость восстановления | Правильный отказ | Правильный отказ | Правильный отказ |

Например, исходный режим правильно назвал порт 18803, но сослался на «Это облачный
вызов, как и генерация ответа». В оптимизированных режимах выбрана цитата про
локальный RAG-сервис и порт 18803. Для истории исправлена ссылка на другой раздел:
цитата теперь прямо говорит о сохранении и восстановлении истории.

Осталась реальная регрессия: в продолжении диалога оба настроенных варианта
предложили `pnpm dev`, хотя спрашивали запуск RAG-сервиса (`pnpm rag:server`).
Поэтому нельзя отключать смысловую проверку или обещать безошибочность профиля.
Первый черновик с этой ошибкой не считается успешным ответом.

Выбор зависит от приоритета: **настроенная Q4 — для меньшего расхода памяти;
настроенная Q8 — кандидат для лучшего качества**, если доступна дополнительная
память. На этом небольшом наборе Q8 получила лучший результат, но независимая
проверка на новых вопросах и длинных диалогах ещё нужна. Смена выбранной модели
остаётся явным действием при создании агента.

## Проверка в настоящем чате

Создан агент **«День 29 · Qwen Q8»**, модель `qwen2.5:7b-instruct-q8_0`,
RAG и память включены, профиль compact. Это отдельная проверка полного пути,
а не продолжение изолированного замера выше.

1. «Готовим инструкцию для нового разработчика. Работаем на macOS, используем
   pnpm. Запомни эти ограничения. Какой порт по умолчанию использует RAG-сервис?
   Где это указано?»

   Получен ответ: «RAG-сервис использует порт 18803 по умолчанию. [S2]».
   Источник — README.md, строки 473–498, чанк
   `3847837557e20649d0e64c9356de50d70bed30eda85fa1fa38b77c2bef44acd3`.
   Цитата: «При отдельном `pnpm dev` запустите ещё `pnpm rag:server`
   (порт 18803, переменная `RAG_PORT`)».

   При этом проверка полноты добавила избыточный отказ на «Где это указано»,
   хотя источник уже присутствует. Это оставшийся дефект оценки полноты;
   он не считается устранённым настройкой генератора.

2. «А какой командой запустить именно RAG-сервис? Учитывай выбранный ранее
   менеджер пакетов. Приведи команду и источник.»

   Получен ответ: «Командой `pnpm rag:server` запускается RAG-сервис на порту
   18803. [S3]». Источник — тот же чанк README, цитата непосредственно
   подтверждает команду. Отказа на этом ходе не было. В памяти остались цель
   запуска RAG-сервиса, macOS и pnpm. Нумерация источников относится к отдельному
   ответу, поэтому один и тот же чанк получил другой номер.

Полный чат также использует подготовку вопроса, повторный поиск и настроенную
смысловую проверку Qwen 27B. Его успешный второй ход не отменяет ошибку первого
черновика в изолированном тесте: условия и состав контекста различаются.

Проверки кода: 558/558 автотестов, TypeScript, oxlint и production-сборка.
Добавлены проверки передачи профиля до Ollama, сохранения настроек, окна памяти,
совместимости идентификаторов цитат и отклонения переполненного контекста до
инференса. При первом запуске тестов песочница блокировала MCP-порты; повторный
полный запуск с доступом к локальным портам прошёл.
